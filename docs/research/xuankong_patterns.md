## 0. 結論摘要

1. 舊引擎 `divine_xuankong.py` 有兩個結構性錯誤(信心: 高)。
   - (a) 24 山陰陽表錯誤。正確:陽 = 乾坤艮巽、甲庚壬丙、寅申巳亥;陰 = 子午卯酉、辰戌丑未、乙辛丁癸。舊表把子午卯酉當陽、寅申巳亥當陰。
   - (b) 順逆判定錯誤。舊碼直接用坐山自己的陰陽;正確做法是「入中之星到它自己的洛書本宮,找與坐山(或向山)同一元龍(地/天/人)的那座山,看那座山的陰陽」。入中星是 5 時才直接用坐山(或向山)自己的陰陽。
   - 實測 216 個(元運 × 坐山)組合,舊引擎格局與正確算法不同者 164 個(76%);九運 24 山全錯;舊引擎會判「九運癸山丁向 = 旺山旺向」,但九運根本沒有旺山旺向。
2. 格局只由兩個順逆位元決定(§1.4 有代數證明):山盤逆且向盤逆 = 旺山旺向;山盤順且向盤順 = 上山下水;山逆向順 = 雙星會坐;山順向逆 = 雙星會向。四種窮盡,216 個組合沒有「其它」。
3. 各運統計(§2.5):旺山旺向共 48 局(二至八運;五運 12 局,其餘各 6 局;一運、九運為 0)。九運 = 12 雙星會坐 + 12 雙星會向,沒有旺山旺向、沒有上山下水(下卦正向)。七運、八運皆為 6/6/6/6。
4. 已驗證(§4):九運與八運各 24 山向格局,對兩個獨立作者的列表全部一致;七運旺山旺向 6 局對兩個來源一致;七星打劫 64 局(離宮 24 + 坎宮 24 + 三般巧卦 16)與公開名單逐項一致;全局合十 24 局、父母三般卦 16 局吻合;九運 21 張星盤的山星/向星/運星數字與公開分析逐宮一致(共 125 個宮位三數組,零差異);本研究引擎與另一份獨立實作 216/216 一致。
5. 財與丁:向星旺 = 旺財,山星旺 = 旺丁(多來源一致)。山盤(地卦)用來看來龍、山砂、神位、床位、桌位;向盤(天卦)用來看水、門路、氣口、梯、窗(SOHU-912417602)。九運下卦每一張盤都是「雙九同宮」:雙九在向宮 = 旺財不旺丁,在坐宮 = 旺丁不旺財(§2.6 有 24 山向對照表)。
6. 五氣建議預設(九運):九紫旺、一白近旺生氣、二黑遠旺生氣、八白退氣、七六五煞衰、四三死氣(§2.4)。八白在九運是「退氣但本性仍是財星」:預設 0 分、不主動催,另設開關保留財星本性。
7. 看盤優先順序:先看山星與向星的組合,其次山運、向運組合,運星最後(SOHU-469457756、108S、YXS-4379 一致)。用途分流:財位/門窗氣口看向星,床位/書桌/健康看山星。
8. 特殊格局的形式化條件已可直接寫成程式(§1.5):全局合十(運山/運向)、父母三般卦、七星打劫(雙星會向 + 同組條件)、全局伏吟/反吟(5 入中)、宮位伏吟/反吟、城門位。連珠/連茹的定義三派互相矛盾,預設只標記不計分。
9. 來源有一條說法經程式反例證明不成立:「五黃入中順飛必是上山下水」。只有山盤與向盤都是 5 順飛時才成立(12 個反例,如一運壬山丙向)。

### 1.2 元運

### 1.3 排盤(運盤、山盤、向盤)

輸入:當運 N(1..9)、坐山 S(24 山之一)。

1. 運盤:N 入中,順飛。`Y[p] = wrap9(N + d(p))`,d(p) 為 p 在順飛路徑上距中宮的步數(中0 乾1 兌2 艮3 離4 坎5 坤6 震7 巽8)。
2. 向山 F = S 的對山;坐宮 pS、向宮 pF。
3. 山盤入中星 a = `Y[pS]`;向盤入中星 b = `Y[pF]`。
4. 順逆:
   - 若入中星 ≠ 5:去該星自己的洛書本宮(1 坎、2 坤、3 震、4 巽、6 乾、7 兌、8 艮、9 離),取該宮中與坐山(向盤則與向山)同一元龍位置的山,看它的陰陽,陽順陰逆。
   - 若入中星 = 5:直接用坐山(向盤用向山)自己的陰陽(信心: 高;CAF-957、108S-292)。另一種寫法「用當運星本宮同元龍山」在 216 張下卦盤上結果完全相同(已用程式驗證),不影響輸出。
5. 山盤:a 入中,依順逆飛遍九宮;向盤:b 入中,依順逆飛遍九宮。

### 1.4 四大格局判定與窮盡性

令 `pS`、`pF` 為坐宮、向宮,`M[p]` 山星、`X[p]` 向星、`Y[p]` 運星:

| 格局 | 條件 | 別名 | 財丁 |
|---|---|---|---|
| 旺山旺向 | `M[pS]==N` 且 `X[pF]==N` | 到山到向 | 丁財兩旺(需形巒配合:坐實朝空、背山面水) |
| 上山下水 | `M[pF]==N` 且 `X[pS]==N` | 丁星下水、財星上山 | 丁財兩損(需反用:坐空朝滿、背水面山才能救) |
| 雙星會向 | `M[pF]==N` 且 `X[pF]==N` | 雙星到向、下水局、七星打劫之基 | 旺財不旺丁 |
| 雙星會坐 | `M[pS]==N` 且 `X[pS]==N` | 雙星到山/到坐、上山局 | 旺丁不旺財 |

(信心: 高;36FS-zs31、36FS-zs33、SOHU-912417602、CAF-series。)

**窮盡性證明。**令 σ、τ 分別為山盤、向盤的飛行方向(+1 順、-1 逆)。對宮的步數互補:`d(pS)+d(pF) ≡ 0 (mod 9)`。運盤 `Y[p]=N+d(p)`。山盤入中星 `a=N+d(pS)`,故
- 山星在坐宮 = `N+(1+σ)d(pS)`,在向宮 = `N+(1-σ)d(pS)`;
- 向盤入中星 `b=N+d(pF)=N-d(pS)`,故向星在向宮 = `N+(1+τ)d(pF)`,在坐宮 = `N+(τ-1)d(pS)`。

因為 `d(pS) ≢ 0 (mod 9)`:σ=-1 ⇒ 山星 N 在坐宮;σ=+1 ⇒ 山星 N 在向宮;τ=-1 ⇒ 向星 N 在向宮;τ=+1 ⇒ 向星 N 在坐宮。所以:

| (σ, τ) | 格局 |
|---|---|
| (-,-) | 旺山旺向 |
| (+,+) | 上山下水 |
| (-,+) | 雙星會坐 |
| (+,-) | 雙星會向 |

只要算出兩個順逆位元就能判格局,不必展開整盤。這與來源的口訣一致:兩星皆陰為旺山旺向、皆陽為上山下水(36FS-zs33;SOHU-297482065)。程式驗證:216/216 組合皆落在四種格局內,無「其它」;`classify()` 對手工替卦盤才可能回傳「其它」。

推論:入中星為 5 且順飛時,該盤(山盤或向盤)與洛書本位完全相同(全局伏吟);5 逆飛時各宮星與本宮數合十(全局反吟),見 §1.5。

### 1.5 特殊格局的形式化條件

**(1) 全局合十(信心: 高;SINA-HESHI)**
- 運山合十:九宮每宮 `Y[p]+M[p]==10`。運向合十:九宮每宮 `Y[p]+X[p]==10`。
- 用途:通氣(通卦),補救一運、九運沒有旺山旺向的缺憾(SINA-HESHI)。程式找到恰好 24 局(§2.7),與公開名單逐局吻合。
- 局部合十:某宮山、向、運三數中任兩數和為 10(SINA-HESHI 的較寬定義),`heshiPalaces()` 回傳這些宮。
- 生成數(河圖):1-6、2-7、3-8、4-9(SINA-3BAN)。對宮合十:1-9、2-8、3-7、4-6。
- 另有「山星與向星對宮合十」與「形局合十」兩種,SINA-HESHI 只舉例(五運坤艮/艮坤/申寅/寅申),未給形式化條件,列入未解決(§6)。
- 旺丁/旺財歸屬:七運子山午向九宮運山全合十(旺丁),反過來午山子向為運向合十(旺財)(僅摘要,cafengshuinet 七運文章經 WebSearch 取得;信心: 中)。

**(2) 三般卦(信心: 父母三般高;連珠/連茹低)**
- 父母三般卦:九宮每宮的山、向、運三數同屬 `{1,4,7}`、`{2,5,8}` 或 `{3,6,9}`(三數對 3 同餘)。程式找到 16 局:二、五、八運的艮山坤向、坤山艮向、寅山申向、申山寅向(12 局),加四、六運的丑山未向、未山丑向(4 局)。SINA-3BAN 稱之為「三般巧卦」,同為 16 局(信心: 高)。SOHU-479770164 說父母三般卦只出現在二五八運艮坤,漏了四、六運丑未(來源不完整)。
- 這 16 局全是上山下水(程式驗證;SOHU-479770164 亦說「全是上山下水」),且可不受上山下水限制(SINA-3BAN 稱「不受上山下水之局限」)。
- 連數三般卦(SINA-3BAN):九宮每宮三數為三個相鄰數(一二三、二三四…九一二)。程式找到 16 局(§2.7)。同一形態在 SOHU-479770164、SOHU-469457756 稱為「連茹」並判凶(前吉後凶);SOHU-469457756 又把「連珠」定義為生成數對(一六、二七、三八、四九)判大吉;中州派說法是連珠 = 父母三般卦。三派互相矛盾,預設只標記不計分(§3 第 5 項)。

**(3) 七星打劫(信心: 高)**
- 前提:雙星會向(下水局)。
- 離宮打劫(真):向宮 ∈ {離,震,乾} 且離、震、乾三宮的所有山星與向星,都屬於當運星 N 的三般組(數字對 3 同餘)。
- 坎宮打劫(假):向宮 ∈ {坎,巽,兌} 且坎、巽、兌三宮的所有山星與向星,都屬於 N 的三般組。
- 程式結果:離宮打劫 24 局、坎宮打劫 24 局,與 SINA-3BAN 名單逐項一致(§2.7);加三般巧卦 16 局,共 64 局。
- 不可用:打劫局若犯全局伏吟(5 順飛)則不可用,共 6 局:巽山乾向六運、巳山亥向六運、壬山丙向九運、丙山壬向一運、乾山巽向四運、亥山巳向四運(SINA-3BAN)。該來源沒有把 5 逆飛(反吟)的打劫局列為不可用。
- 尚有 12 張「雙星會向、向宮在艮或坤、且艮中坤三宮皆屬 N 組」的盤(一運、三運的艮山坤向/寅山申向/未山丑向;七運、九運的丑山未向/坤山艮向/申山寅向),SINA-3BAN 的 64 局不含這些,本實作也不列入(§6)。

**(4) 伏吟、反吟(信心: 中高;ZGGDFS-57、ZGGDFS-60、GENDAI、CAF-2984)**
- 全局伏吟:山盤或向盤入中星為 5 且順飛,該盤與洛書本位完全相同。
- 全局反吟:入中星為 5 且逆飛,該盤各宮星與本宮洛書數合十(星飛到對宮)。
- 宮位伏吟:某宮(不含中宮)山星或向星等於該宮洛書數,或等於該宮運星。
- 宮位反吟:某宮山星或向星與該宮洛書數合十。
- 山向配卦 64 卦翻卦法(ZGGDFS 第三種):本實作未涵蓋,列入未解決。
- 判讀:全局伏吟屬難以調解的凶格(ZGGDFS-57 建議換屋)。反吟因為是逆飛,當旺運形巒配合仍可發,退運立敗(ZGGDFS-60);山盤反吟主人口、意外,向盤反吟主敗財、投機(ZGGDFS-60)。宮位伏吟若該宮星旺可用,衰死則絕不用(ZGGDFS-57)。
- 來源中「犯反伏吟」的標記慣例:SOHU-912417602 標的八運艮/寅/坤/申四個山向與九運壬丙、丙壬,程式判定全是全局伏吟(5 順);另標八運甲山庚向,程式查得其向宮(兌)向星 3 與洛書數 7 合十(宮位反吟);5 逆飛(全局反吟)的盤如九運子山午向不被標記。

### 1.7 財丁位判讀流程與看盤優先順序(信心: 中,權重為工程折衷)

1. 對每個宮位 p 取三個數 `M[p]`、`X[p]`、`Y[p]`。
2. 財分 `cai(p) = qiScore(X[p]) + 0.3*qiScore(Y[p]) + 0.3*qiScore(M[p]) + 組合調整`;丁分 `ding(p) = qiScore(M[p]) + 0.3*qiScore(Y[p]) + 0.3*qiScore(X[p]) + 組合調整`。0.3 是工程折衷,對應「山向組合為主、山運/向運為輔、運星最後」。
3. 組合調整:依 `pairTagsOfPalace()` 的吉凶標籤(吉 +0.5、凶 -1;二五在二運/五運不扣;六九視旺衰)。
4. 玄空旺財位 = `cai` 最高且 `X[p]` 屬 N/N+1/N+2 的宮;玄空旺丁位 = `ding` 最高且 `M[p]` 屬 N/N+1/N+2 的宮。九運 24 山向的實例見 §2.6。
5. 「用途分流」:大門、窗、氣口、客廳動線看向星(財);床位、書桌、神位看山星(丁與健康)。SOHU-912417602 明說山盤看來龍、山砂、神位、床位、桌位,向盤看水、門路、氣口、梯、窗、空凹。
6. 啟動條件:飛星只在氣口(門、窗、冷氣機)被催旺時才應驗,大門最重要(YXS-4379);向星宜動(水、窗口、乾淨的動水),山星宜靜、宜有靠。
7. 優先順序的三種說法(§3 第 7 項):(i)山向組合 > 山運/向運 > 運星(SOHU-469457756、108S);(ii)山星 > 向星 > 流年星(36FS-zs30,用在流年疊加);(iii)坐星為主、向星為客、運星最後(YXS-4379)。預設:找財位以向星為主,找人丁/床位以山星為主,運星只用作旺衰基準。
8. 與流年疊加(其他主題):2026 丙午年流年中宮為 1,東 8、東南 9、南 5、西北 2(以順飛公式重算;與 HK 媒體所述一致,僅摘要,信心: 中)。九運的流年財星是 9、1、8,可疊在 §2.6 的宮位上。

### 1.10 JS 參考實作(已對 216 張盤與 474 個測試向量驗證)

```js
// Reference implementation: Xuan Kong Flying Star chart (山向盤) + pattern detection.
// Pure functions, no DOM, no dependencies. Works in Node and browsers (Capacitor WebView).
// Palace numbers are Luo Shu numbers: 1 坎(N) 2 坤(SW) 3 震(E) 4 巽(SE) 5 中 6 乾(NW) 7 兌(W) 8 艮(NE) 9 離(S).

const PALACE_NAME = { 1: '坎', 2: '坤', 3: '震', 4: '巽', 5: '中', 6: '乾', 7: '兌', 8: '艮', 9: '離' };
const PALACE_DIR = { 1: '北', 2: '西南', 3: '東', 4: '東南', 5: '中', 6: '西北', 7: '西', 8: '東北', 9: '南' };
// Forward (順) flight order of palaces after the entering star sits in the centre.
const FLY_ORDER = [5, 6, 7, 8, 9, 1, 2, 3, 4]; // 中 乾 兌 艮 離 坎 坤 震 巽

// 24 mountains grouped by palace: [地元龍, 天元龍, 人元龍]
const MOUNTAINS = {
  1: ['壬', '子', '癸'], 8: ['丑', '艮', '寅'], 3: ['甲', '卯', '乙'], 4: ['辰', '巽', '巳'],
  9: ['丙', '午', '丁'], 2: ['未', '坤', '申'], 7: ['庚', '酉', '辛'], 6: ['戌', '乾', '亥'],
};
// Polarity per palace, same order [地, 天, 人]; +1 陽(順飛) / -1 陰(逆飛).
// 陽 = 乾坤艮巽 甲庚壬丙 寅申巳亥 ; 陰 = 子午卯酉 辰戌丑未 乙辛丁癸
const POLARITY = {
  1: [1, -1, -1], 8: [-1, 1, 1], 3: [1, -1, -1], 4: [-1, 1, 1],
  9: [1, -1, -1], 2: [-1, 1, 1], 7: [1, -1, -1], 6: [-1, 1, 1],
};
const ORDER24 = ['壬', '子', '癸', '丑', '艮', '寅', '甲', '卯', '乙', '辰', '巽', '巳',
  '丙', '午', '丁', '未', '坤', '申', '庚', '酉', '辛', '戌', '乾', '亥']; // clockwise from 壬 (345 deg)
const MOUNTAIN_INFO = {}; // mountain -> {palace, slot(0地/1天/2人), yuan, sign}
for (const p of Object.keys(MOUNTAINS)) {
  MOUNTAINS[p].forEach((m, i) => {
    MOUNTAIN_INFO[m] = { palace: Number(p), slot: i, yuan: ['地', '天', '人'][i], sign: POLARITY[p][i] };
  });
}

const wrap9 = (n) => ((n - 1) % 9 + 9) % 9 + 1;

/** Centre star `center` flies through all palaces. sign=+1 forward, -1 backward. */
function fly(center, sign) {
  const out = {};
  FLY_ORDER.forEach((p, i) => { out[p] = wrap9(center + sign * i); });
  return out;
}

/** Direction of flight (+1/-1) for `star` entering the centre, judged against reference mountain `ref` (坐山 or 向山).
 *  Star 5 has no home palace: follow the reference mountain's own polarity (mainstream rule). */
function polarityFor(star, ref) {
  if (star === 5) return MOUNTAIN_INFO[ref].sign;
  return POLARITY[star][MOUNTAIN_INFO[ref].slot];
}

function oppositeMountain(m) { return ORDER24[(ORDER24.indexOf(m) + 12) % 24]; }

/** Build the three plates for period `yun` (1..9) and sitting mountain `sit`. */
function buildChart(yun, sit) {
  const face = oppositeMountain(sit);
  const yunPan = fly(yun, +1);
  const sitPalace = MOUNTAIN_INFO[sit].palace;
  const facePalace = MOUNTAIN_INFO[face].palace;
  const shanCenter = yunPan[sitPalace];
  const xiangCenter = yunPan[facePalace];
  const shanSign = polarityFor(shanCenter, sit);
  const xiangSign = polarityFor(xiangCenter, face);
  return {
    yun, sit, face, sitPalace, facePalace,
    yunPan, shanCenter, xiangCenter, shanSign, xiangSign,
    shan: fly(shanCenter, shanSign), xiang: fly(xiangCenter, xiangSign),
  };
}

/** Four classic patterns. Exhaustive for plain (下卦) charts: 山逆向逆 旺山旺向 / 山順向順 上山下水 /
 *  山逆向順 雙星會坐 / 山順向逆 雙星會向. Returns '其它' only for hand-made (替卦) charts. */
function classify(ch) {
  const N = ch.yun, S = ch.sitPalace, F = ch.facePalace;
  const sS = ch.shan[S] === N, sF = ch.shan[F] === N, xS = ch.xiang[S] === N, xF = ch.xiang[F] === N;
  if (sS && xF) return '旺山旺向';
  if (sF && xS) return '上山下水';
  if (sS && xS) return '雙星會坐';
  if (sF && xF) return '雙星會向';
  return '其它';
}

/** 全局合十: 運+山 or 運+向 sums to 10 in all nine palaces. */
function heshi(ch) {
  const all = (a, b) => [1, 2, 3, 4, 5, 6, 7, 8, 9].every((p) => a[p] + b[p] === 10);
  if (all(ch.yunPan, ch.shan)) return '運山';
  if (all(ch.yunPan, ch.xiang)) return '運向';
  return null;
}

/** 父母三般卦 (all palaces: 山,向,運 in the same group {1,4,7}/{2,5,8}/{3,6,9}) == 三般巧卦 (艮坤). */
function parent3(ch) {
  return [1, 2, 3, 4, 5, 6, 7, 8, 9].every((p) => {
    const g = ch.yunPan[p] % 3;
    return ch.shan[p] % 3 === g && ch.xiang[p] % 3 === g;
  });
}

/** 連數三般卦 (all palaces: 山,向,運 are three distinct consecutive numbers, cyclic). Definition disputed. */
function lianshu3(ch) {
  return [1, 2, 3, 4, 5, 6, 7, 8, 9].every((p) => {
    const s = new Set([ch.yunPan[p], ch.shan[p], ch.xiang[p]]);
    if (s.size !== 3) return false;
    for (let a = 1; a <= 9; a++) {
      if (s.has(a) && s.has(wrap9(a + 1)) && s.has(wrap9(a + 2))) return true;
    }
    return false;
  });
}

/** 七星打劫: 雙星會向 chart whose 山星 and 向星 in the three palaces of the 向宮's cluster all belong to N's group.
 *  Clusters: 離震乾 (離宮打劫, 真), 坎巽兌 (坎宮打劫, 假). Returns null when not applicable. */
function qixing(ch) {
  if (classify(ch) !== '雙星會向') return null;
  const cluster = [[9, 3, 6], [1, 4, 7]].find((c) => c.includes(ch.facePalace));
  if (!cluster) return null;
  const g = ch.yun % 3;
  if (!cluster.every((p) => ch.shan[p] % 3 === g && ch.xiang[p] % 3 === g)) return null;
  return { kind: cluster[0] === 9 ? '離宮打劫' : '坎宮打劫', group: [g, g + 3, g + 6].map((x) => (x === 0 ? 9 : x)).sort((a, b) => a - b).join('') };
}

/** Whole-plate 伏吟/反吟: entering star 5 flying forward = 伏吟 (plate == Luo Shu), backward = 反吟. */
function wholePlate(ch) {
  const f = (center, sign) => (center === 5 ? (sign > 0 ? '伏吟' : '反吟') : null);
  return { shan: f(ch.shanCenter, ch.shanSign), xiang: f(ch.xiangCenter, ch.xiangSign) };
}

/** Palace-level 伏吟 (star == Luo Shu home number, or == period star) and 反吟 (star + home == 10). Centre excluded. */
function localYin(ch) {
  const out = { fuyin: [], fanyin: [] };
  for (const p of [1, 2, 3, 4, 6, 7, 8, 9]) {
```
