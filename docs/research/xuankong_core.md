## 一、結論摘要

1. **山向盤規則已完全確定並經程式逐格驗證**。以本報告第二章的演算法重算, 與 Wikibooks 公開的 9 運 x 24 山 = 216 個下卦山向盤逐格全部一致 (216/216); 與《玄空風水函授初級教材》(中州派) 書中 80 個下卦盤例全部一致 (80/80, 涵蓋 51 個相異的「運 x 坐山」); Wikibooks 216 個替卦盤亦 216/216 一致。(信心: 高)
2. **本專案舊表的 24 山陰陽是錯的**。你們手上的版本 (陽 = 乾坤艮巽 + 子午卯酉 + 甲庚丙壬) 把「子午卯酉」當陽、「寅申巳亥」當陰, 與至少 5 個彼此獨立的來源 (星林學苑、三六風水網、易先生、Wikibooks、中州派書/加拿大中心) 正好相反。玄空正確表: 陽 (順飛) = 乾坤艮巽 + 壬丙甲庚 + 寅申巳亥; 陰 (逆飛) = 子午卯酉 + 辰戌丑未 + 乙辛丁癸。舊表共 8 山寫反 (子午卯酉寅申巳亥)。(信心: 高)
3. **舊程式 `divine_xuankong.get_shan_xiang_pan` 在 216 個公開盤中只有 52 個正確 (24%)**。錯因有三: (a) 陰陽表寫反; (b) 缺少「二次轉換」(入中星要先回到洛書卦宮, 再取該宮內與坐/向山同元龍的那一山來判陰陽), 直接用坐山自己的陰陽; (c) 向山用「對宮內同陰陽的第一座山」, 應為坐山的對山 (24 山環上 +12 位, 同元龍)。消融實驗: 只修表 = 60/216; 只修演算法 (保留舊表) = 104/216; 兩者都修 = 216/216。(信心: 高)
4. **順逆判定的一句話**: 入中星 (運盤上坐山宮或向山宮的星) 先當洛書卦宮數, 找該宮內與坐 (向) 山同元龍的那一山, 看它的陰陽: 陽順飛、陰逆飛。等價的免查表寫法: 入中星為奇數 (1,3,7,9) 時, 地元龍順、天人元龍逆; 入中星為偶數 (2,4,6,8) 時, 地元龍逆、天人元龍順。已用程式驗證 216 x 2 = 432 次飛布全部相符。(信心: 高)
5. **5 入中**: 用坐 (向) 山自身的陰陽即可。《函授教材》另一種說法「以運盤中宮運星所在卦宮的同元龍山代」與此完全等價 (程式驗證 216/216 盤結果相同; 原因是 5 飛臨的宮與中宮運星的宮必同屬四正卦或同屬四隅卦)。無常派口訣「如逢廉貞五黃土, 歸附山向順逆行」亦為此意。(信心: 高)
6. **每宮排列**: 左上山星、右上向星、下方運星 (「左山右向」); 4 個獨立來源一致。(信心: 高)
7. **三元九運**: 九運 = 2024-02-04 16:27 (立春, 香港天文台 HKT) 至 2044 年立春。**2044 年立春在 2044-02-04 中午 (約 12:43 至 12:50 CST), 不是 02-03**; 因此 2044-02-03 全日與 2044-02-04 上午仍是九運。(信心: 高; 分鐘級數值 2044 年因預測誤差約 6 分鐘, 中)
8. **入運**: 主流是以房屋「建成/落成」的運起盤 (不是當下年份); 若之後做過「大修 / 改換天心」則以最近一次大修完工時的運為準; 《函授教材》(中州派) 則主張以「遷入」時為準。大修的判準沒有共識, 建議 App 用「整戶翻新 (含天花) 才換運」的保守預設並給開關。(信心: 中)
9. **兼向**: 每山 15 度, 中間 9 度 (距中線 ±4.5 度) 用下卦; 外側各 3 度為兼向。兼向只在「出卦」或「陰陽差錯」時才用替卦; 同卦同陰陽相兼 (天元兼人元) 不替。此規則與 Wikibooks 48 個兼向扇區逐一吻合 (48/48)。(信心: 高; 是否啟用替卦屬流派選擇)
10. **替星表有兩套**: A 表 (蔣大鴻歌訣, 經《沈氏玄空學》流傳, 中州派 13 山替法同此) 多數來源與 Wikibooks 一致; B 表 (陳澤泰《陽宅鏡》「三元挨星訣」, 無常派秘傳) 只見於無常派。替卦後的順逆看「原本那一山」的陰陽, 不看替星。**建議預設: 只做下卦 + 兼向提示, 替卦 (A 表) 放進階選項。**
11. **九運 24 山全部只有「雙星會向」或「雙星會坐」各 12 盤, 沒有旺山旺向與上山下水** (程式推得, 與台灣命學研究中心文章所列 9 個九運旺財座向皆為雙星會向一致)。App 在九運的「吉凶敘述」要據此設計。(信心: 高)

## 二、規則與演算法 (逐步, 可直接寫成程式)

### 2.1 座標與名詞

- 洛書宮數: 坎1 坤2 震3 巽4 中5 乾6 兌7 艮8 離9。星數 = 宮數 (二次轉換就是靠這個)。
- 顯示格局 (南在上): 上排 巽4 離9 坤2; 中排 震3 中5 兌7; 下排 艮8 坎1 乾6。
- 24 山環: 自正北偏西的「壬」起順時針, 每卦三山依序為 地元龍、天元龍、人元龍: 壬子癸 / 丑艮寅 / 甲卯乙 / 辰巽巳 / 丙午丁 / 未坤申 / 庚酉辛 / 戌乾亥。子山中心 = 0 度, 壬 = 337.5 至 352.5 度, 每山 15 度。
- 坐山 = 房屋背面所朝的山; 向山 = 正面所朝的山 = 坐山的對山 = 環上 +12 位 (壬↔丙, 子↔午, 癸↔丁 ...)。對山必與坐山同元龍、同陰陽 (24/24 已驗)。
- 「山星入中」= 運盤上坐山所在宮的星; 「向星入中」= 運盤上向山所在宮的星。

### 2.2 運盤 (B)

運星以當運數入中宮, 一律順飛, 宮位次序 (洛書順序): 中5 → 乾6 → 兌7 → 艮8 → 離9 → 坎1 → 坤2 → 震3 → 巽4。
公式: 第 i 個宮 (i = 0..8) 的星 = ((運 - 1 + i) mod 9) + 1。(信心: 高; 來源: 星林學苑 292、無常派 155、加拿大中心 957、Wikibooks 9 頁)

八運例: 中8 乾9 兌1 艮2 離3 坎4 坤5 震6 巽7 (見資料表 3.1)。

### 2.3 山向盤 (D) 演算法

### 2.5 由羅盤度數到山、下卦/兼向 (E)

輸入朝向 (向的方位角 deg, 順時針自正北):
```
x = (deg - 337.5) mod 360;  i = floor(x / 15);  off = x - 15*i;  delta = off - 7.5
山 = 環[i]
|delta| <= 4.5            -> 下卦 (正向)
4.5 < |delta| < 7.5       -> 兼向; delta<0 兼前一山(環 i-1), delta>0 兼後一山(環 i+1)
    兼到別卦宮            -> 出卦   -> 用替卦
    同卦但陰陽不同 (地元龍與天元龍互兼) -> 陰陽差錯 -> 用替卦
    同卦同陰陽 (天元龍與人元龍互兼)     -> 不替 (仍用下卦盤)
|delta| >= 6.0 (兼向外側 1.5 度)        -> 警示: 落在大/小空亡線帶
```
24 條山界線的分類見資料表 3.3: 8 條「出卦 (大空亡線)」、8 條「陰陽差錯 (小空亡線)」、8 條「同陰陽 (小空亡線)」, 因此 48 個兼向扇區中 32 個用替、16 個不替 (與 Wikibooks Substitute Star 表 48/48 吻合)。(信心: 高)
端點慣例: 中州派度數表 (340.5 至 349.5 下卦) 含端點, 有文章寫「9 度以外 (含 9 度) 為兼向」, 恰為 ±4.5 度的端點值屬慣例分歧 (信心: 低), 程式實作取 |delta| <= 4.5 為下卦並建議在 UI 提示「騎線」。

### 2.6 替卦 (進階)

- 替星 A 表 (蔣大鴻歌訣: 子癸並甲申貪狼一路行 / 壬卯乙未坤五位為巨門 / 乾亥辰巽巳連戌武曲 / 酉辛丑艮丙破軍 / 寅午庚丁上右弼): 子癸甲申→1; 壬卯乙未坤→2; 乾亥辰巽巳戌→6; 酉辛丑艮丙→7; 寅午庚丁→9。其中 11 山替星等於自己原星 (等於不替), 實際會改變數字的只有 13 山: 甲申壬卯乙艮丑丙巽辰巳庚寅。
- 起法 (中州派 / Wikibooks / 無常派範例一致): 先照下卦找出「入中星所在宮內、與坐(向)山同元龍的那一山」(伴), 用伴查替星表得到入中數; **順逆仍看伴 (原本元龍) 的陰陽, 不看替星**; 5 入中不替。
- 程式驗證: 此法與 Wikibooks 的 216 個替卦盤逐格全同; 若改用「替星所在宮」的陰陽決定順逆則與書中範例大量不符。

### 2.7 參考實作 (JS, 已驗證: 對全部 568 個 fixture case 零差異)

```js
'use strict';
// 24 山, 自壬(337.5度)順時針: [名, 洛書宮, 元龍(0地 1天 2人)]
const RING = [
  ['壬',1,0],['子',1,1],['癸',1,2],['丑',8,0],['艮',8,1],['寅',8,2],
  ['甲',3,0],['卯',3,1],['乙',3,2],['辰',4,0],['巽',4,1],['巳',4,2],
  ['丙',9,0],['午',9,1],['丁',9,2],['未',2,0],['坤',2,1],['申',2,2],
  ['庚',7,0],['酉',7,1],['辛',7,2],['戌',6,0],['乾',6,1],['亥',6,2],
];
const NAMES = RING.map(r => r[0]);
const IDX = Object.fromEntries(NAMES.map((n, i) => [n, i]));
const PALACE = Object.fromEntries(RING.map(r => [r[0], r[1]]));
const YUAN = Object.fromEntries(RING.map(r => [r[0], r[2]]));
const YANG = new Set('壬丙甲庚乾坤艮巽寅申巳亥'.split(''));      // 陽=順飛; 其餘 12 山為陰=逆飛
const FLY_ORDER = [5,6,7,8,9,1,2,3,4];                          // 中 乾 兌 艮 離 坎 坤 震 巽
const TI_A = {};                                                // 替星 A 表
[['子癸甲申',1],['壬卯乙未坤',2],['乾亥辰巽巳戌',6],['酉辛丑艮丙',7],['寅午庚丁',9]]
  .forEach(([g, s]) => g.split('').forEach(ch => { TI_A[ch] = s; }));
const mod9 = n => ((n - 1) % 9 + 9) % 9 + 1;

function fly(center, forward) {                                  // -> {宮: 星}
  const out = {};
  FLY_ORDER.forEach((p, i) => { out[p] = mod9(forward ? center + i : center - i); });
  return out;
}
const opposite = m => NAMES[(IDX[m] + 12) % 24];
const mateIn = (palace, m) => RING.find(r => r[1] === palace && r[2] === YUAN[m])[0];
function direction(star, m) {                                    // 二次轉換; 5 入中用山自身
  const mate = star === 5 ? m : mateIn(star, m);
  return { forward: YANG.has(mate), mate };
}
function buildChart(yun, sit, opts) {                            // opts.ti: 替卦(A 表)
  const useTi = !!(opts && opts.ti), face = opposite(sit), yp = fly(yun, true);
  const part = m => {
    const star = yp[PALACE[m]], d = direction(star, m);
    const enter = (useTi && star !== 5) ? TI_A[d.mate] : star;
    return { star, enter, forward: d.forward, mate: d.mate, pan: fly(enter, d.forward) };
  };
  const s = part(sit), x = part(face), cells = {};
  for (let p = 1; p <= 9; p++) cells[p] = { yun: yp[p], shan: s.pan[p], xiang: x.pan[p] };
  return { yun, sit, face, cells, shanEnter: s.enter, xiangEnter: x.enter,
           shanForward: s.forward, xiangForward: x.forward };
}
function locate(deg) {                                           // 度數 -> 山 / 下卦 or 兼向 / 是否用替
  const x = ((deg - 337.5) % 360 + 360) % 360, i = Math.floor(x / 15), delta = x - i * 15 - 7.5;
  const m = NAMES[i];
  if (Math.abs(delta) <= 4.5 + 1e-9) return { mountain: m, delta, zone: 'xia', needTi: false };
  const side = delta < 0 ? 'pre' : 'post';
  const nb = NAMES[(i + (side === 'pre' ? -1 : 1) + 24) % 24];
  const cross = PALACE[m] !== PALACE[nb], yy = YANG.has(m) !== YANG.has(nb);
  return { mountain: m, delta, zone: 'jian', side, neighbor: nb, needTi: cross || yy,
           kind: cross ? '出卦' : (yy ? '陰陽差錯' : '同陰陽'), outer: Math.abs(delta) >= 6.0 - 1e-9 };
}
```

### 2.8 與 App 的接口建議

`輸入: 向的方位角(或選 24 山) + 入運年(見 2.9) + 是否啟用替卦` → `locate()` 得向山與兼向提示 → 坐山 = `opposite(向山)` → `buildChart(運, 坐山, {ti: 啟用替卦 && needTi})` → 每宮三數。前端的平面圖要把「向」朝向對應羅盤方位, 九宮 (南在上) 只是數據排版。

### 2.9 三元九運與入運 / 換運 (A)

**運界**: 以立春 (太陽黃經 315 度) 交運; 三元九運 180 年循環, 起點 1864 (甲子)。任意年 y 的運 (以立春調整過的年份 cy): `運 = floor(((cy - 1864) mod 180) / 20) + 1`。只有 (y - 1864) mod 20 = 0 的交運年需要「立春時刻」, 其餘年份看年份即可。

要點:

- 交運日不一定是 2/4: 1904、1924、1944、1964 年的立春在 2/5, 1984 年立春在 2/4 23:19 (差 41 分鐘就跨日)。App 若只收「日期」而沒有時間, 落在交運日當天要提示「請輸入時間或確認」。
- 星林學苑 290 將一運寫成 1846 是筆誤 (應為 1864); 其餘所有來源為 1864。

程式 (已驗證 22 個交運日前後的 case):

```js
const LICHUN = { // [月, 日, 時, 分] CST(UTC+8); 只有交運年 (y-1864)%20==0 需要
  1804:[2,5,6,44],1824:[2,5,3,12],1844:[2,4,23,42],1864:[2,4,20,13],1884:[2,4,16,45],
  1904:[2,5,13,24],1924:[2,5,9,50],1944:[2,5,6,23],1964:[2,5,3,5],1984:[2,4,23,19],
  2004:[2,4,19,56],2024:[2,4,16,27],2044:[2,4,12,45],2064:[2,4,9,14],2084:[2,4,5,41],
  2104:[2,5,2,10],2124:[2,4,22,41] };
function yunOf(y, mo, d, hh = 12, mi = 0) {
  let cy = y;
  if (((y - 1864) % 20 + 20) % 20 === 0) {
    const t = LICHUN[y];
    if (Date.UTC(y, mo - 1, d, hh, mi) < Date.UTC(y, t[0] - 1, t[1], t[2], t[3])) cy = y - 1;
  }
  return Math.floor((((cy - 1864) % 180 + 180) % 180) / 20) + 1;
}
```

**入運 (房屋用哪一年的運起盤)**: 三派做法 (詳見第四章分歧):
1. 落成 / 建成年的運 (主流; 香港玄燊師傅「大廈落成年份等於大廈出生時間, 即八字」; 星林學苑 290「元運的定義是房子建好的年份, 並非搬進去的時間」)。
2. 遷入 (入伙) 時的運 (中州派《函授教材》: 「看何時遷入此宅, 再看遷入後有無大裝修」)。
3. 若有大修則以最近一次大修完工當時的運 (各派皆承認; 星林學苑稱「改換天心」)。

**大修 (換運) 的常見判準** (無統一標準, 信心: 低):
- 星林學苑 290: 整個重新裝潢, 包含空調都換新 (改換天心), 才可改以新運入中。
- 中州派: 並非所有裝修都能換運; 若要換運, 裝修同時最好敲掉房間中心的天花頂、遷出約百日再大裝修。
- 台灣命學研究中心 (幸福空間專欄): 以「重新裝潢」時的運為準 (九運後重新裝潢即成九運盤)。
- 論壇 (痞客邦) 反映師傅之間「兩極化」: 有人認為只要地基與結構未改就沒有換天心; 有人認為元運到了自動換。
