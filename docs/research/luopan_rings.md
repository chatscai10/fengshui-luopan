## 0. 先講清楚的三件事

1. **網頁摘要會出錯,所以表格都用原始 HTML / wikitext 抓下來再用程式對照。** 例如某站的二十四山表被 AI 摘要成錯誤順序(丑、巳、申、亥不見了),這類內容一律不採用。
2. **抓不到或不可信的來源(已明講,未採用)**:曹盛健的 udn 部落格(HTTP 403 Access Denied)、知乎(403)、百度百科(403)、`fengshui-college.org`(網域內容已被博弈廣告取代,棄用)。
3. **傳統羅盤沒有「唯一標準盤」。** 三合盤、三元盤、綜合盤的環序、陰陽分法、二十八宿宿度都不同。本檔的做法是:把可算的規則寫成演算法,不可判定的地方並列各派說法,再給「建議預設」與「可選開關」。

## 1. 結論摘要

**白話版(給不看程式的人)**

- 羅盤盤面其實就是「一圈一圈的表格」。最裡面是天池(指南針),往外依序是八卦、洛書數字、二十四山(最重要的一圈)、二十四節氣、二十八星宿,最外面是 360 度刻度。
- 二十四山把一圈 360 度切成 24 份,每份 15 度,**正北「子」山的正中央就是 0 度**。屋子朝向幾度,就對到哪一山。
- 傳統盤有兩套「陰陽」算法(玄空/三元派 與 三合派),所以同一個字可能一套算陰、一套算陽。App 要同時存兩套,預設用玄空(因為我們要算玄空飛星、八宅)。
- 二十八宿在羅盤上各占的度數不一樣(最寬 30 度,最窄 0.5 度),最窄的「觜」「鬼」兩個字在手機上塞不下,要用引線或錯位擺放。
- 畫面做法:盤面只畫一次,之後轉動只是把整張圖旋轉(很省電、不卡),手指拖曳加上慣性,就是電視上那種輪盤轉向的感覺。

**工程重點(每條已在第 2 至 5 節展開)**

1. 座標:**北在上、方位角順時針、子山中心 = 0°**;Canvas 角度 = (方位角 − 90)°;半開區間 [起, 迄)。24 山範圍與 Wikipedia 表 24/24 一致。(信心: 高)
2. 環序共通規律(3 種盤 + 1 張實物照片交叉):天池最內,二十八宿與 360 度最外;八卦環在 24 山內側;**二十四節氣環緊貼在地盤 24 山外側**;人盤、天盤是「把 24 山整圈轉半格」的複製環。(信心: 中高)
3. 手機版 **7 個資料環 + 天池 = 8 環**,「節氣」與「人盤+天盤」二擇一,最多 9 環。(信心: 高,屬設計決定)
4. 三針:人盤 = 地盤逆時針轉 7.5°(子中心在 352.5°),天盤 = 順時針 7.5°(子中心在 7.5°)。有一個來源用相反的「左右」措辭,已列入分歧。(信心: 中)
5. 陰陽兩套並存:**三元龍陰陽**(乾巽艮坤寅申巳亥甲庚丙壬為陽)與**三合紅黑字**(子癸申辰午壬寅戌乾甲坤乙為紅=陽)。兩套集合都已用規則重新推導並與多個來源比對一致。(信心: 高)
6. 三元龍:每個八卦宮內順時針依序為 地元、天元、人元。(信心: 高)
7. 二十八宿:採「開禧宿度」,28 個寬度總和恰為 365.25 古度,乘 360/365.25 縮進 360° 盤;**子中心 = 虛危之間**;**方位角增加的方向,宿序是反著走的(危→虛→女→牛→斗)**,這是最容易畫反的地方。以獨立文章的圓周度比對,最大誤差 0.71°。(信心: 中)

## 2. 規則與演算法

### 2.1 座標與命名約定(所有環共用)

| 項目 | 約定 |
|---|---|
| 方位角 b | 度,從正北起**順時針**,0 ≤ b < 360;子山中心 = 0° |
| 區間 | 半開 [起, 迄);跨 0° 的山(子:352.5→7.5)以 (b − 起) mod 360 判斷 |
| Canvas 角度 | `rad = (b − 90) * π / 180`(Canvas 0 = +x 向東,順時針為正) |
| 字元位置 | 環半徑 r、方位角 b:`x = cx + r·sin(b)`, `y = cy − r·cos(b)`;字頭朝外時 `ctx.rotate(b)` |
| 上方向 | 預設**北在上**(與手機指北一致)。傳統「前南後北」圖是南在上(Wikipedia 八卦條目敘述),做成「南上」開關 = 整盤 +180° |

### 2.4 逐環演算法(可直接寫成程式)

**步驟 1:方位角 → 山(地盤 / 人盤 / 天盤共用)**

```js
const M24 = [...'子癸丑艮寅甲卯乙辰巽巳丙午丁未坤申庚酉辛戌乾亥壬'];   // 順時針,子中心 0°
const SHIFT = { di: 0, ren: -7.5, tian: +7.5 };                           // 該盤「子」的中心方位角
function mountainAt(b, plate = 'di') {
  const i = Math.floor((((b - SHIFT[plate]) % 360 + 360) % 360 + 7.5) / 15) % 24;
  return { index: i, name: M24[i], center: (15 * i + SHIFT[plate] + 360) % 360 };
}
```

**步驟 2:山 → 八卦宮 / 三元龍 / 陰陽 / 五行**

```js
const PALACE = ['坎','艮','震','巽','離','坤','兌','乾'];        // 每宮 45°,中心 45*k
const palaceOf = i => PALACE[Math.floor(((i + 1) % 24) / 3)];
const yuanOf   = i => ['地元','天元','人元'][(i + 1) % 3];      // 宮內順時針:地、天、人
function yinYangSanYuan(name, yuan) {                            // 玄空/三元盤
  if (yuan === '天元') return '子午卯酉'.includes(name) ? '陰' : '陽';
  if (yuan === '地元') return '甲丙庚壬'.includes(name) ? '陽' : '陰';   // 辰戌丑未 陰
  return '乙丁辛癸'.includes(name) ? '陰' : '陽';                        // 寅申巳亥 陽
}
const YANG_SANHE = new Set([...'乾坤甲乙癸申子辰壬寅午戌']);     // 三合紅字;其餘為黑字(陰)
```

**步驟 3:八卦 / 洛書**

`bearing = 45 * k`(坎 0、艮 45、震 90、巽 135、離 180、坤 225、兌 270、乾 315);洛書數 坎1 坤2 震3 巽4 乾6 兌7 艮8 離9(中5),對宮相加 = 10,傳統南上排列為 `[[4,9,2],[3,5,7],[8,1,6]]`,8 條線和皆 15。卦爻(初→上,1=陽):乾111 兌110 離101 震100 巽011 坎010 艮001 坤000。**卦象請用 Canvas 畫三條線**(陽=實線、陰=中斷),不要依賴 ☰ 等字元(Unicode U+2630–2637,舊 Android 字型可能缺字)。

**步驟 4:二十八宿(開禧宿度)**

```js
// 古度寬(角亢氐...軫,天文序),太=+.75 少=+.25 半=+.5,合計 365.25
const W = [12.75,9.75,16.25,5.75,6,18,9.5, 22.75,7,11,9.25,16,18.25,9.75,
           18,12.75,15.25,11,16.5,0.5,9.5, 30.25,2.5,13.5,6.75,17.75,20.25,18.75];
const NAMES = [...'角亢氐房心尾箕斗牛女虛危室壁奎婁胃昴畢觜參井鬼柳星張翼軫'];
const K = 360 / 365.25;
// 方位角由 0° 起順時針:先排「虛」,之後宿序倒著走(虛→女→牛→斗→箕→尾→心→房→氐→亢→角→軫→...→壁→室→危)
const ORDER = Array.from({ length: 28 }, (_, k) => (NAMES.indexOf('虛') - k + 28) % 28);
let acc = 0;
const XIU = ORDER.map(i => { const s = acc; acc += W[i]; return { name: NAMES[i], start: s * K, end: acc * K, endGu: acc }; });
// 入宿度:從該宿「天文起點」(方位角較大的那端)算起的古度
const ruSu = b => { const x = XIU.find(x => b >= x.start && b < x.end); return { xiu: x.name, degree: x.endGu - b / K }; };
```

fixture 有 `xiu28_lookup_*` 與「午中落張第 3 度」的驗算(ruSu(180) = 張,2.125 度)。
